## 3. 发现并修复的问题

1. **结果栏被挤出视口**
   - 原因：消息栏 `hidden` 后，CSS Grid 自动排布改变了子元素所在的行，结果栏落到视口下方。
   - 修复：给工具栏、消息栏、阅读区、结果栏显式指定 `grid-row`，并给 viewer 设置 `height: 100%`。
   - 复核：结果栏底边为 720px，和视口高度一致。

2. **页码输入框过窄**
   - 原因：`4.2ch` 加内边距后宽度不足。
   - 修复：加宽到 `5.2ch`，并设置 `min-width`。

3. **按 Enter 跳页在自动化中不稳定**
   - 修复：Enter 键处理中直接调用 `goToPage()`，不再只依赖 blur 后的 `change` 事件。
   - 复核：输入 4 + Enter 能跳到第 4 页。

4. **Vite 旧进程占用 5173**
   - 现象：重启后新服务跑到 5174，旧进程继续提供旧 CSS。
   - 处理：停止旧 Vite 进程，使用 `--strictPort` 重新启动 5173。这个问题是开发过程问题，不是应用代码问题。

5. **arXiv PDF 首次下载不完整**
   - 现象：PDF.js 报“文件可能已损坏”。
   - 原因：代理截断，磁盘文件 1.9 MB，服务器声明 2.2 MB。
   - 重新完整下载后验证通过。说明错误提示是有效的，不是应用误报。

## 4. 已知未解决问题

- **句子点击方式不够显眼**：当前点击单词读单词，只有点击句子内单词之间的空白才读整句。后续应增加明确的“整句”按钮或模式切换。
- **只有模拟提示音**：不是真人发音，不能验证单词读音。Phase 4 接入合法音频并缓存。
- **照片 OCR 未实现**：RapidOCR/ONNX Runtime 未安装，`requirements-ocr.txt` 留到 Phase 3。
- **扫描版 PDF 只提示**：不执行 OCR。
- **原生文件选择框未自动化**：浏览器自动化环境不支持系统文件对话框；测试通过文件输入的 `change` 事件和拖放路径验证，仍需人工点击“打开 PDF”确认一次。
- **复杂版式未全面验证**：arXiv 第 1 页是标题/版权页；多栏正文、表格、脚注、跨页句子的切分仍需更多真实书籍样本。
- **大文件性能未专门压测**：当前限制 100 MB，按页提取；超大 PDF 的内存和响应时间还需测试。
- **移动端 UI 未做真机验收**：Phase 1 主要面向电脑端，手机拍照属于 Phase 3。

## 5. 结论

Phase 1 的验收标准已满足：

- 能打开真实 PDF。
- 能在原版页面上点击英文单词，结果正确。
- 翻页、缩放、滚动、旋转页后点击位置仍然正确。
- 扫描版 PDF 明确提示，没有伪造识别结果。
- 坐标映射、PDF 提取和 API 有自动化测试。

未完成项已明确记录，没有把模拟音频或扫描页 OCR 说成已实现。
