# 照片 OCR 方法与限制

- 日期：2026-10-20
- 引擎：RapidOCR 3.10.0（默认 PP-OCRv6 small）+ ONNX Runtime CPU
- 运行方式：完全在本机处理，不调用云端 OCR
- 代码：`backend/app/services/photo_ocr.py`

## 1. 处理流程

1. 手机浏览器通过 `<input type="file" accept="image/*" capture="environment">` 拍照或选图。
2. 图片以 multipart 上传到本机 FastAPI，最大 25 MB；用 Pillow 校验并解码。
3. 用 `ImageOps.exif_transpose` 按 EXIF 方向校正，转换为 RGB。
4. 生成显示图（长边最多 3000px，JPEG 92）和 OCR 图（长边最多 2000px，保持宽高比）。
5. RapidOCR 以 `return_word_box=True` 运行。
6. 用 OCR 图的宽高归一化所有坐标到 `0..1`；该坐标对显示图同样有效。
7. 原照片（校正后）保存到 `data/photos/{uuid}.jpg`，最小元数据保存到同名 `.json`；OCR 文本只保存在本次响应/内存中。

## 2. 单词级坐标

实测英文结果中，`word_results` **直接返回单词框**，例如：

```text
("The", 0.99998, [[108,120], [174,120], [174,173], [108,173]])
("quick", 0.99998, [[187,120], [288,120], [288,173], [187,173]])
```

因此：

- 本项目直接使用这些单词框，**不从整行框按比例切分**，也不猜测每个单词的位置。
- 对单词文本用英文正则清理首尾标点（如 `dog.` -> `dog`），但点击框仍覆盖 OCR 返回的原始单词范围。
- 如果 OCR 没有返回单词框（`word_results` 为空），单词列表为空，界面显示“OCR 没有返回单词级坐标”；不会用行框伪造单词。
- 如果某些 OCR 模式返回逐字符框（CJK 常见），代码检测到“整行有空格但所有 token 都只有一个字符”时放弃这些 token，回退为整行句子点击，不把字符框当英文单词。
- API 返回 `word_box_method` 明示上述策略。

## 3. 行与句子

- 行：使用 OCR 的 `boxes`/`txts`，保留行文本和 bbox。
- 句子：按 OCR 阅读顺序累计 token，遇到 `.?!` 等句末标点结束；一个句子可以跨多行。
- 每个句子同时返回：
  - `bbox`：所有 token 的联合区域（调试用）；
  - `segments`：每行一个片段，前端按片段建立点击框，避免多行句子的联合大框覆盖别的句子。
- 没有单词框的行仍可产生句子片段，因此“只看句子”仍可用，但单词点击不会凭空出现。

## 4. 坐标与屏幕

- 后端只返回归一化 bbox `[x0,y0,x1,y1]`，原点为显示图左上角。
- 前端图片和两层点击框都在同一个 `photo-stage` 中。
- 缩放/拖动只修改这个容器的 CSS transform（translate + scale），图片与点击框一起变换。
- 因此无需把 OCR 坐标换算成屏幕像素，缩放、拖动后仍对齐。
- 浏览器验证：156% 放大、180% 双指缩放、拖动后，点击框相对图片的位置与 bbox 一致。

## 5. 图像质量与错误处理

| 情况 | 行为 |
| --- | --- |
| 空文件 | 400“上传的照片为空” |
| 非图片/损坏 | 400“无法读取这张图片” |
| 小于 200px | 400“照片太小” |
| 超过 25 MB | 413 |
| 超过 8000 万像素 | 400“分辨率过大” |
| 没有识别到文字 | 照片仍显示，提示“尽量正对、拍清晰、光线均匀” |
| 只有中文/数字 | 照片显示，提示“没有检测到英文单词” |
| OCR 依赖缺失/异常 | 照片仍保存并显示，提示 OCR 失败 |
| 单词级坐标缺失 | 不生成单词框，提示只能句子点击 |
| OCR 置信度低 | 仍返回结果，并显示质量警告 |
| 部分行无单词框 | 其他行仍可点词，警告那些行只能按句子点击 |

## 6. 实际测试

- 生成 1200×1600 书页图片（5 段英文、不同行长度）：
  - OCR 约 1.3 秒；
  - 49 个单词框、7 行、6 个句子；
  - 单词框和句子框归一化正确。
- 倾斜 7° 的英文页面：17 个单词、2 个句子，仍可识别。
- 空白 600×400 图片：0 个单词，显示“没有识别到文字”提示。
- 中文 900×500 图片：0 个英文单词，显示“当前只支持英文点读”提示。
- EXIF Orientation=6 的 JPEG：上传后宽高正确交换为 400×600。
- 浏览器 390×844 移动视口：图片显示、点词、整句、缩放、拖动、清空均验证。

## 7. 限制

- 低清晰度、运动模糊、反光、阴影、手指遮挡、倾斜/透视都会降低 OCR 准确率；当前没有自动去倾斜、去模糊或透视校正。
- 多栏页面的 OCR 顺序可能按检测结果而不是严格阅读顺序；跨栏句子可能切分不理想。
- 手写、艺术字、特殊字体、图表中的文字不可靠。
- 词典/音标/页眉页脚可能被识别为正文，尚未过滤。
- 单词框来自 OCR，不保证与人眼看到的每个词完全一致；界面会显示识别结果，便于发现错误。
- 当前只支持英文点读；OCR 虽支持中文，但中文不会生成英文单词点击。
- 图片显示会缩小超大照片，原始分辨率不保留；归一化坐标不受影响。
- 照片不会上传云端；清空照片会删除当前本地文件。
